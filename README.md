# Olores Bot — заявки, жалобы, баги

## Запуск
1. https://discord.com/developers/applications → New Application → Bot → скопируй токен.
   Включи **Server Members Intent** и **Message Content Intent** (второй нужен, чтобы в логах была переписка тикета). Пригласи бота со скоупами `bot` + `applications.commands`
   и правами: Send Messages, Embed Links, Attach Files, Read Message History, View Channel.
2. `pip install -r requirements.txt`
3. Скопируй `.env.example` в `.env`, вставь токен.
4. Положи шрифт с кириллицей в `fonts/bold.ttf` (Montserrat Bold / Unbounded / Inter с Google Fonts).
5. `python bot.py`

## Настройка в Discord
- `/setup` — каналы: заявки, жалобы, баги, категория для тикетов, статистика и **канал логов**. Каналы заявок/жалоб/багов и логов должны быть видны только персоналу.
- `/setup_roles` — роль администрации и роли, обрабатывающие заявки, жалобы и баги.
- `/panel_app`, `/panel_report`, `/panel_bug` — отправь в публичный канал панель нужного раздела.
- `/stats`, `/stats_user`, `/weekly_post` — статистика (админка), `/status` — публичная статистика.
- `/queue` — открытые обращения, срочные первыми (персонал). Кнопка «🔥 Срочно» под карточкой ставит и снимает приоритет.
- `/ticket раздел номер` — данные обращения и переписка из базы, даже если канал тикета уже удалён.
- `/settings` — проверка ника (`mc_check`), пауза после отказа (`reapply_days`), автозакрытие при молчании игрока (`auto_close_days`), копия базы в канал логов (`backup_discord`), ошибки бота в канал логов (`error_log`), вайтлист по RCON (`whitelist`). Без параметров показывает текущие значения.
- `/access` — в тикете показывает, какие роли видят канал и почему (админка).
- `/block`, `/unblock`, `/blocked` — закрыть игроку подачу заявок в проект, снять запрет, список (админка).
- `/health` — аптайм, память, размер базы, последняя резервная копия (админка).
- `/quote` и пункты меню сообщения «Цитата» / «Цитата (тёмная)» — оформление цитаты картинкой, можно приложить фон. Бот отправляет её от имени автора через вебхук (нужно право «Управлять вебхуками», иначе обычным сообщением). ⭐ на цитате — в избранное: `/quotes favorites`, случайная цитата: `/quotes random`.

## Как работает
Игрок жмёт кнопку → форма → карточка падает в канал персонала. Канал тикета создаётся только после «Взять в работу» и виден взявшему, игроку и администраторам; модератору приходит ссылка на него.
Кнопки: Подробнее (полный текст виден только тебе), Взять в работу, Принять/Решено/Исправлено, Отклонить (с причиной). После решения тикет закрывается для записи, а заявка с перепиской уходит в канал логов.
Если заявку уже взяли — остальные увидят, кто ей занимается. Игроку приходят уведомления в ЛС.

## Напоминания
- Новое обращение: под карточкой бот тегает роль-обработчика этого раздела (она должна быть упоминаемой или у бота должно быть право «Упоминать все роли»). Если за сутки никто не взял, тег повторяется один раз.
- Обращение в работе: если в тикете тихо больше суток, бот тегает в самом тикете того, кого ждёт: взявшего (если последним писал игрок или никто) или игрока (если последним ответил сотрудник). Повтор не чаще раза в сутки.
- Если включено `/settings auto_close_days`, обращение закрывается как отклонённое, когда игрок молчит дольше этого срока.

## Автоматический вайтлист (необязательно)
Принятый игрок добавляется на сервер Minecraft по RCON. Включается переменными окружения на хосте (пароль в репозиторий не кладём): `RCON_HOST`, `RCON_PASSWORD`, `RCON_PORT` (по умолчанию 25575), `RCON_WHITELIST_CMD` (по умолчанию `whitelist add {nick}`). На сервере в `server.properties` нужны `enable-rcon=true`, `rcon.port` и `rcon.password`, а порт должен быть доступен хосту бота. В команду попадают только ники из 3-16 латинских букв, цифр и «_», остальные добавляются вручную. Результат виден модератору и в логе. Без переменных функция выключена.

## Данные и обслуживание
- Всё хранится в папке `data/` (путь меняется переменной `DATA_DIR`): база `data.db`, настройки серверов (внутри базы), логи `logs/bot.log` (с ротацией) и суточные копии базы `backups/` (последние 7). Папка в `.gitignore`.
- При первом запуске старые `data.db` и `config.json` из корня копируются в `data/` (исходные файлы не удаляются). В репозитории этих файлов больше нет и они в `.gitignore`.
- Ошибки бота (уровень ERROR) дублируются в канал логов, суточную копию базы можно присылать туда же (`/settings backup_discord`).
- Защита от злоупотреблений: не больше 5 обращений в час, пауза после отказа в заявке, проверка ника Minecraft: формат и дубли отклоняются сразу, а «нет такого ника у Mojang» только помечается в заявке (на сервере бывают игроки без лицензии; при недоступности Mojang пометки нет).

## Разработка
```
pip install -r requirements.txt pytest
python -m pytest
```
Структура: `bot.py` — точка входа, `core.py` — объект бота, права, поиск участников, `tickets.py` — карточка, кнопки, тикет, закрытие, `forms.py` — форма и проверки заявки, `commands.py` — слэш-команды, `jobs.py` — фоновые задачи, `stats.py` — статистика, `store.py` — база, настройки, копии, `kinds.py` — виды обращений, `quotes.py` — цитаты, `cards.py` — картинки, `mojang.py` — проверка ника.
